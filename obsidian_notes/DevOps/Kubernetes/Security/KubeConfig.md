
## 📌 Definition

- What it is:
  `kubeconfig` is a configuration file used by `kubectl` and other Kubernetes tools to interact with a Kubernetes cluster. It contains details such as the cluster address, user credentials, namespaces, and context settings.

- How useful it is:
  It allows you to manage access to one or more Kubernetes clusters seamlessly without hardcoding credentials or cluster info each time. It’s essential for secure and convenient cluster management.

- How to implement:
  It's usually located at `~/.kube/config` by default. It can be auto-generated by tools like `kubeadm`, `gcloud`, or `eksctl`, or manually configured.

- Simple analogy:
  Think of it like a **login vault** or a **passport** that lets you switch between different Kubernetes clusters and user roles easily—just like switching bank accounts in a banking app.

- Problem it solves:
   It handles **authentication, authorization, and cluster targeting** without needing to repeatedly provide flags or credentials.

- Attributes:
	  - Supports multiple clusters
	- Can store multiple user credentials
	- Supports context switching
	- Often stored in `~/.kube/config` but can be overridden

- My thoughts:
  It's yaml format file that store all necessary information to manage your k8s cluster, even switch between them.

## 🛠 Commands / Syntax

```bash
# View current context
kubectl config current-context

# View all contexts
kubectl config get-contexts

# Set current context
kubectl config use-context <context-name>

# Add a new cluster manually
kubectl config set-cluster <cluster-name> --server=https://<ip>:6443 --certificate-authority=ca.crt

# Set credentials
kubectl config set-credentials <user> --token=<your_token>

# Set context
kubectl config set-context <context-name> --cluster=<cluster-name> --user=<user>

# Switch context
kubectl config use-context <context-name>


```

  

## 🗒️ YAML format example with explaining if needed

```YAML

  apiVersion: v1
kind: Config
clusters:
- name: dev-cluster
  cluster:
    server: https://192.168.1.100:6443
    certificate-authority-data: <base64-encoded-CA>
users:
- name: dev-user
  user:
    token: <authentication-token>
contexts:
- name: dev-context
  context:
    cluster: dev-cluster
    user: dev-user
current-context: dev-context


```
